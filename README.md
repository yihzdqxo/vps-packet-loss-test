## 丢包是谁的问题？先看丢包范围

判断思路很简单：看丢包的范围。全网节点都在丢、或者间歇性完全连不上，多半是机房级的问题；只有个别节点丢，换个节点复测一般就正常，不用管它。

机房级的问题主要有三类。攻击是最戏剧性的一种：搬瓦工的DC6、DC9机房出现过UDP泛洪攻击导致丢包率飙到90%以上的情况，工单一开始查不出原因，大量用户反馈后才定位，最后靠ACL过滤特定流量解决，遇到这种事你能做的只有等官方处理或者切到别的机房。海缆故障是第二种，太平洋方向的TPE S1S光缆历史上出过多次故障，每次都会拖累洛杉矶一带的机房，光缆修好自然恢复。第三种最普遍：线路本身的问题，入门的CN2 GT线路在国际出口拥堵时会被限速，晚上8点到11点丢包是常态，搬瓦工社区里“入门套餐别用来建站”的说法就是这么来的。

自己VPS的问题更容易被误判成丢包，排查起来也最便宜：

- **宕机或没开机**：SSH连不上、ping不通，先登录KiwiVM面板看状态，宕机重启就好
- **流量耗尽**：月流量用完系统会自动暂停VPS，表现和丢包几乎一样，在面板的Bandwidth页面看本月用量就能确认
- **防火墙误伤**：改过iptables规则的话，某些包可能被自己DROP掉了，清一遍规则通常解决
- **IP被封**：特征很明确，国内ping不通，国外节点正常。换IP目前收费$8.79一次；SLA套餐每两周可以免费换一次

## 丢包率多少算严重？

10%是分水岭。参考标准如下：

- 0–5%：完全可接受，基本无感
- 5–10%：偶尔卡，勉强能用
- 10%以上：明显卡顿，该处理了
- 20%以上：基本没法正常使用

测的时候有个技巧：晚高峰（晚上8点到11点）丢包率全网普遍偏高，白天测一次、晚上再测一次，对比着看才能看出线路的真实水平。白天0%、晚上30%的线路，和全天5%的线路，是两种东西。

## 常见问题

**测出来丢包率0%，为什么用起来还是卡？**

先查带宽和延迟。丢包率低不代表延迟低，美西机房到国内物理延迟就要150ms起步；再看看CPU和内存是不是吃满了。这几个问题换线路解决不了，办法是套CDN、开BBR、升级配置。

**只有某一家运营商的节点丢包，要紧吗？**

先换几个节点复测，排除偶发丢包，单节点丢包多半是测速路径的问题。如果联通、移动、电信某一家整行都是红的，基本可以确定是那条线路的问题，这时候切机房或升线路才有意义。

**怎么区分IP被封和丢包？**

国内ping不通、国外节点ping正常，基本就是IP被封，只能换IP（$8.79一次），SLA套餐每两周免费换一次。丢包则表现为各个节点都有不同程度的损失，两者的处理路径完全不同。
